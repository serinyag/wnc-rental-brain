# Phase 8.4 - Structured Phase 7 Workflow Consumption Runtime

Date completed: 2026-08-10

## Scope

Phase 8.4 implements the deterministic workflow-consumption boundary between finalized Phase 7 reasoning and downstream Phase 8 workflow orchestration.

Implemented:

- workflow-consumption result and effect contracts
- deterministic Phase 7 consumption repository interfaces and in-memory implementation
- stable consumption entry point `consume_phase7_context(...)`
- case-scoped revision validation before reasoning projection persistence
- case-scoped projection identity key generation for idempotent replay
- deterministic workflow posture derivation from structured authority state
- workflow-effect derivation from persisted reasoning projections only
- SQL support for new projection identity and workflow-safety fields
- focused Python and DB regression coverage

Explicitly not implemented:

- freeform answer or prose interpretation as workflow truth
- lifecycle mutation
- case-fact mutation
- blocker, approval, action, or decision creation
- outbound providers, agents, or answer generation

## Contract Layer Added

`tools/phase_08_workflow/phase7_consumption_types.py` now defines:

- workflow reasoning effect taxonomy
- workflow reasoning posture contract
- Phase 8 consumption result states and failure codes
- `WorkflowReasoningEffect`
- `WorkflowReasoningPosture`
- `Phase7ConsumptionResult`

Key contract invariants:

- workflow effects accept non-negative source case revisions
- workflow effect and posture codes are closed sets
- successful consumption results must include both projection and posture
- failure results remain explicit through governed failure codes

## Repository Layer Added

`tools/phase_08_workflow/phase7_consumption_repository.py` adds:

- `Phase7ConsumptionCaseSnapshot`
- `Phase7ConsumptionRepositoryProtocol`
- `InMemoryPhase7ConsumptionRepository`
- `SupabasePhase7ConsumptionRepository`

This layer keeps persistence responsibilities narrow:

- load the case and existing reasoning projections
- look up idempotent projection identity keys
- create append-only workflow reasoning projections

No workflow mutation is introduced here.

## Stable Entry Point

`tools/phase_08_workflow/phase7_workflow_consumer.py` adds the stable application entry point:

- `consume_phase7_context(...)`

The runtime flow is now:

1. validate `ContextPackage` shape and supported Phase 7 contract version
2. fail closed if the target `RentalCase` is missing or stale for the expected revision
3. validate that current, guidance, historical, and grounding references remain structurally aligned
4. derive aggregate reasoning state from layer execution, item reasoning state, and unresolved authority
5. derive deterministic workflow posture from authority outcome plus unresolved and degraded state
6. build a case-scoped projection identity key from the structured reasoning payload
7. return the existing projection if an identical projection already exists for the case
8. persist the new `WorkflowReasoningProjection`
9. derive structured workflow effects from the persisted projection only

## Safety Boundaries Preserved

Phase 8.4 preserves the frozen contract boundary:

- `ContextPackage` is the canonical input
- `answer_text` is never read for workflow truth
- historical precedent cannot silently become current authority
- unresolved authority, conflict, contamination, and degraded retrieval remain explicit
- confidentiality and PI posture constrain projection metadata without mutating lifecycle state
