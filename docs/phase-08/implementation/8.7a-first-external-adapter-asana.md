## Adapter Design

`tools/phase_08_workflow/asana_adapter.py` is split into:

- `AsanaAdapterConfig`
- `UrllibAsanaTransport`
- `AsanaExecutionAdapter`

Responsibilities:

- config validates provider availability
- transport owns HTTP/auth/TLS behavior
- adapter translates governed workflow payloads into Asana task requests and normalizes provider outcomes

## Payload Translation

Supported action:

- `CREATE_INTERNAL_TASK_ITEM`

Supported governed fields:

- `task_kind`
- `summary`
- `reason`
- `task_surface_project_id`
- `task_surface_section_id`
- `task_surface_assignee_id`
- `task_surface_due_on`
- `task_surface_context_lines`

No arbitrary workflow JSON is passed through to Asana.

## Persistence Guardrails

The successful provider task reference continues to live on the existing `ExecutionAttempt.external_reference` field.

Additional protection added:

- Python in-memory completion rejects successful cross-action external-reference reuse
- Supabase completion helper now rejects the same conflict deterministically
- successful external references are backed by a unique partial index
