## Size Fallback Behavior

Pilot safeguard:

- approximate maximum chunk size: `450` tokens

Token counting approach:

- deterministic regex token approximation inside the Python chunker

Fallback order:

1. semantic section
2. paragraph-group split inside the same section
3. no sentence-breaking fallback beyond that

Observed pilot outcome:

- oversized semantic sections encountered: `0`
- fallback splits applied: `0`

The safeguard exists and is tested, but the selected pilot corpus did not require it.

## Source Locator Strategy

Chunk provenance uses deterministic structural locators appropriate to each format:

- manual DOCX: `Heading path: ...`
- template library DOCX: `Template heading: ...`
- checklist DOCX: `Checklist section: ...`
- workbook rows: `Worksheet "...", row N, ...`

Per-chunk provenance is stored in `private.knowledge_chunk_sources`.

Chunk-set extraction provenance is stored in `private.knowledge_chunk_set_sources`.

Each current pilot chunk set uses one current governed extraction source:

- `OPS-001` -> current preferred authoritative editable DOCX
- `TPL-006` -> current preferred authoritative editable DOCX
- `TPL-007` -> current preferred authoritative editable DOCX
- `SERV-001` -> current preferred authoritative workbook

## Regeneration Strategy

Document versions remain immutable governed rows.

Chunk generations are derived rows.

Implemented regeneration model:

- one current chunk set per document version
- prior current generation becomes `superseded`
- new generation rows coexist historically
- governed document-version rows are not replaced

The database tests explicitly cover:

- current/superseded lifecycle
- coexistence of multiple generations
- unchanged governed document-version truth

## Issues Discovered

Semantic/output issues discovered:

- `OPS-001` chunk `Wall and beam use` is unusually short and should be reviewed by a human before later retrieval approval
- `TPL-006` template chunks intentionally keep usage notes, variables, subject line, and body text together; later application layers should still distinguish internal notes from client-sendable text
- `TPL-007` required explicit section gating so the Discovery Call logical document did not accidentally ingest the Site Visit logical section from the same physical file
- `SERV-001` `Controlled lists` is semantically valid but lower-value than service-row chunks and may later be better treated as supporting context rather than top-tier retrieval content

Provenance/governance issues discovered:

- `OPS-001` remains a controlled draft at the governance layer even though its extraction identity is reliable
- `TPL-007` shares its physical file with `TPL-008`, so section boundaries must remain explicit in future regeneration work
- `SERV-001` contains `facilitator_sourcing` guidance that references the deferred facilitator catalogue boundary and should not be mistaken for activating `SERV-002`
- chunk-level rule relationships remain intentionally deferred pending semantic review

## Deviations / Blockers

- the local `supabase db query` write path proved unreliable for large multi-statement pilot loads because it obscured actionable SQL failures during development
