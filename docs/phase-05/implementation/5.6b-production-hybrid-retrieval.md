# Phase 5.6B Production Hybrid Retrieval

Date: August 7, 2026

## Scope

Task 5.6B translates the approved 5.6A `rrf_policy_weighted` design into the private production retrieval layer.

This implementation does not:

- change FTS vector construction
- change FTS weighting
- change embeddings or cosine similarity
- change chunk boundaries
- change corpus governance or search eligibility
- generate answers or build RAG

It adds the deterministic fusion layer that sits above the existing FTS and semantic search substrates.

## Private Retrieval Surface

The production database entrypoint is:

- `private.search_knowledge_chunks_hybrid(...)`

Supported inputs:

- `query_text`
- `query_embedding`
- `result_limit`
- `candidate_pool_limit`
- optional `embedding_model_id`
- optional `document_code`
- optional `category_code`
- optional `rental_type_code`

Behavior:

1. normalize and reject empty/whitespace-only query text safely
2. run FTS candidate retrieval from `private.search_knowledge_chunks`
3. run semantic candidate retrieval from `private.search_knowledge_chunks_semantic` when a query embedding is supplied
4. fuse candidates by chunk identity
5. apply deterministic reciprocal rank fusion
6. apply governed category modifiers
7. return explainable ranked chunk rows

If `query_embedding` is omitted, the surface degrades deterministically to the FTS-only candidate path while still applying category modifiers and current-governance eligibility.

## RRF Implementation

Approved constant:

- `k = 20`

Helper function:

- `private.hybrid_retrieval_rrf_score(rank, k)`

Formula:

```text
rrf_score = 1 / (k + rank)
```

The hybrid function calculates:

- `rrf_fts_score`
- `rrf_semantic_score`
- `rrf_base_score = rrf_fts_score + rrf_semantic_score`

Raw FTS and cosine scores are not blended directly.

## Governed Policy Modifier Implementation

Helper function:

- `private.hybrid_retrieval_policy_modifier(category_code)`

Implemented corpus-wide modifiers:

- `operational_procedure`: `+0.011`
- `communication_guidance`: `+0.009`
- `service_supplier_guidance`: `+0.007`
- `technical_venue_reference`: `+0.007`
- `client_facing_controlled_document`: `+0.005`
- `proposal_guidance`: `+0.001`
- `governance_canonical`: `-0.010`

Not implemented:

- query-specific boosts
- document-code-specific boosts
- chunk-rule boosts
- document-rule boosts
- authority-classification weight

Those were intentionally rejected in 5.6A and remain rejected here.

## Candidate Depth

Production candidate depth per substrate:

- `10`

Why:

- fusion needs more than the final result window to preserve complementary FTS and semantic candidates
- the corpus is small enough that this remains simple and explainable
- it is a narrow production implementation choice above the approved 5.6A policy, not a new ranking strategy

Final captured result window in the CLI/evaluator defaults to:

- `5`

## Result Shape

The hybrid result returns:

- chunk identity and body fields
- document code and title
- document version identifiers
- section and heading metadata
- provenance pointers
- `primary_category_code`
- `authority_classification`
- rental-type applicability
- source-presence booleans:
  - `came_from_fts`
  - `came_from_semantic`
- source ranks:
  - `fts_rank`
  - `semantic_rank`
- source scores:
  - `fts_relevance_score`
  - `semantic_similarity_score`
  - `semantic_cosine_distance`
- explainability components:
  - `rrf_k`
  - `rrf_fts_score`
  - `rrf_semantic_score`
  - `rrf_base_score`
  - `policy_modifier`
  - `final_score`

This keeps ranking reviewable and governance-friendly.

## Query Tooling

Interactive retrieval tool:

- `python3 -m tools.phase_05_search.search_hybrid "query text"`

This tool:

- normalizes the query
- generates the query embedding with the active retrieval-approved embedding model unless `--fts-only` is set
- calls the private hybrid SQL function
- prints deterministic ranked results or JSON

Evaluation tool:

- `python3 -m tools.phase_05_search.evaluate_hybrid`

This tool is intended to run the original 13 fixtures plus holdouts against the production hybrid surface once live embeddings are present after reset.

## Security Posture

The same private-only posture applies to:

- `private.search_knowledge_chunks_hybrid`
- `private.hybrid_retrieval_rrf_score`
- `private.hybrid_retrieval_policy_modifier`
