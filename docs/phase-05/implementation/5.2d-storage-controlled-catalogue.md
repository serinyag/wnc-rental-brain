## Catalogue / Bootstrap Mechanism

Final mechanism:

- deterministic bootstrap inside `supabase/seed.sql`

Reason:

- the local Supabase seed runner used by `npx supabase db reset` executed `seed.sql` as plain SQL and did not support psql include directives such as `\ir`
- a separate included catalogue SQL file was evaluated first, but it broke local reset determinism for this repository
- the final repository-controlled bootstrap therefore keeps the 5.2D catalogue section inside `seed.sql` so reset remains one-step and deterministic

This preserves:

- clean local rebuilds
- reviewability in version control
- stable code-based lookups instead of environment-specific IDs

## Idempotency Approach

The bootstrap is rerunnable and deterministic through stable keys:

- `knowledge_documents` keyed by `document_code`
- `knowledge_document_versions` keyed by `(document_id, version_number)`
- current corpus rows keyed through the one-current-row-per-document index
- `knowledge_source_objects` keyed by origin-specific locator uniqueness
- M:N links keyed by their existing uniqueness constraints
- logical-rule links keyed by `(document_version_id, rule_code, relationship_type_id)`

The implementation uses upserts or conflict-safe inserts rather than environment-specific IDs.
