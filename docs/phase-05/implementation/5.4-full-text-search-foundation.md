# Phase 5.4 Full-Text Search Foundation

Date: August 7, 2026

## Scope Implemented

Task 5.4 added the first deterministic keyword/full-text retrieval layer on top of:

- 5.2A Core Governance Foundation
- 5.2B Security Hardening
- 5.2C Source Provenance & Rule Connectivity
- 5.2D Storage & Controlled Knowledge Catalogue
- 5.3A Semantic Chunking Foundation
- 5.3B Pilot Refinement & Rule Connectivity
- 5.3C Bulk Semantic Chunking

This implementation added:

- a stored weighted PostgreSQL `tsvector` on `private.knowledge_chunks`
- a GIN index for chunk retrieval
- a private current-eligible search surface
- a private ranked search function with safe query parsing
- deterministic FTS evaluation tooling
- dedicated pgTAP coverage for search eligibility, ranking, filters, and security posture

This task did not add:

- embeddings
- `pgvector`
- semantic/vector search
- fuzzy search extensions such as `pg_trgm`
- public RPCs
- application-layer answering
- LLM orchestration
- proposal generation

## Search Vector Design

Final implementation:

- storage model: generated stored column
- text-search configuration: `english`
- parser: `websearch_to_tsquery`
- ranking: `ts_rank_cd`

Weighted fields:

- `A`: `document_title_snapshot`
- `B`: `section_heading`
- `B`: `heading_path`
- `B`: `question_label`
- `D`: `body_text`

Why `english` was selected:

- the governed corpus is English operational, commercial, and policy material
- no corpus review evidence justified a custom dictionary or non-English configuration
- `english` gives stemming and stop-word handling without introducing speculative repository complexity

## Current-Eligible Search Surface

The private search surface is `private.current_knowledge_chunks`.

Eligibility requires all of the following:

- current corpus decision row with `corpus_status = 'include'`
- current corpus-state record flagged `is_current`
- governed document version status `active`
- effective date window valid on the query date
- chunk set status `current`
- chunk belongs to that current chunk set
- chunk has at least one exact source trace

This excludes from current search:

- deferred documents
- draft governed versions
- superseded chunk sets
- future-effective governed versions
- chunks without exact provenance

Validated current searchable state after bulk reload on August 7, 2026:

- searchable current documents: `21`
- searchable current chunk sets: `21`
- searchable current chunks: `492`

The difference from the full current chunk inventory is intentional:

- total current chunks loaded by 5.3C: `525`
- `OPS-001` remains draft and therefore excluded from current search
- `GOV-003` remains draft and is excluded
- `CF-001` still has no approved safe deterministic parser output

## Search Function

Created private function:

- `private.search_knowledge_chunks(p_query_text text, p_result_limit integer default 10, p_document_code text default null, p_category_code text default null, p_rental_type_code text default null)`

Supported behavior:

- ordinary phrase and multi-word search via `websearch_to_tsquery`
- empty-input handling without errors
- bounded result limits
- deterministic rank ordering
- optional filters already supported by governed metadata:
  - document code
  - primary category code
  - rental type code

Returned fields preserve retrieval provenance, including:

- governed document identity and version number
- chunk ordinal and headings
- rank score
- content hash
- primary chunk-source trace
- primary document-version source object
- source locator
- primary category code
- rental-type applicability
