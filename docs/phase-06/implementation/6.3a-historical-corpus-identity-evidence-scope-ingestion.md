# Phase 6.3A Historical Corpus Identity, Evidence & Scope Ingestion

Date: August 7, 2026

## Summary

Task 6.3A is the first production historical-corpus ingestion step for Phase 6.

It loads:

- the nine stable historical case identities
- justified alias rows
- one first governed draft case version per case
- the shared Historical Case Library as a reusable source object
- one case-specific evidence association per case version
- precedent-topic assignments
- canonical rental-type assignments where justified
- canonical venue-space assignments where justified

It intentionally stops before responsibilities, decisions, lessons, current-authority relationships, and activation.

## Ingestion Mechanism

Production Stage A corpus data is loaded in:

- `supabase/seed.sql`

That choice follows the existing repository convention for controlled bootstrap data:

- `source_registry`
- `knowledge_source_objects`
- controlled Phase 4 / Phase 5 bootstrap catalogues

Why `seed.sql` was used instead of a new migration:

- this is production corpus bootstrap content rather than a schema change
- the data must survive `npx supabase db reset`
- the repository already seeds shared source-object identity and controlled production catalogue data through the seed path

The Stage A block is written to be deterministic on rerun:

- `historical_cases` upsert on `case_code`
- `historical_case_versions` upsert on `(historical_case_id, version_number)`
- the shared Historical Case Library `knowledge_source_object` upserts on `repository_relative_path`
- aliases, topics, rental types, spaces, and the curated library association reconcile against the controlled Stage A seed set for these nine cases
