# Phase 6.4B Historical Full-Text Search Foundation

Date: August 7, 2026

## Scope Implemented

Task `6.4B` adds the first deterministic lexical retrieval layer over the governed historical search-unit surface created in `6.4A`.

This implementation adds:

- a stored weighted PostgreSQL `tsvector` on `private.historical_case_search_units`
- a GIN index for historical lexical retrieval
- a private server-side historical search function
- deterministic lexical ranking with explicit tie-breaking
- governed historical filters
- deterministic historical FTS evaluation
- dedicated pgTAP coverage for search behavior, filters, safety metadata, and private posture

This task does not add:

- embeddings
- vector search
- semantic retrieval
- hybrid or RRF retrieval
- current-plus-historical result fusion
- RAG
- answer generation

## Query Parsing

The function uses:

- PostgreSQL text-search configuration: `english`
- parser: `websearch_to_tsquery`

Normalization steps:

- `coalesce` null query to empty text
- collapse repeated whitespace with `regexp_replace`
- `btrim` outer whitespace
- treat empty or whitespace-only input as no-query and return zero rows
- parse the normalized text with `websearch_to_tsquery`
- if `numnode(tsquery) = 0`, return zero rows

This keeps query handling deterministic and avoids dynamic SQL.

## Ranking

Ranking uses:

- `ts_rank_cd(search_vector, parsed_query, 2)`

The `2` normalization factor was chosen so shorter exact statement units do not routinely lose to much longer narrative units when both contain the same phrase.

Deterministic ordering:

1. lexical score descending
2. `case_code`
3. `unit_type`
4. `search_unit_id`

This keeps repeated identical searches stable.

## Filters

Supported filters:

- `case_code`
- `unit_type`
- `precedent_availability`
- `precedent_type`
- `lesson_kind`
- `historical_value_only`
- `contamination_risk_level`

Null/default behavior:

- null filter means no restriction
- case code is normalized with `upper(trim(...))`
- enum-like filters are normalized with `lower(trim(...))`
- unsupported filter values raise `22023`

Narrative-unit behavior:

- narrative rows do not carry `lesson_kind`
- narrative rows do not carry statement-level `historical_value_only`
- narrative rows do not carry statement-level `contamination_risk_level`

So when those statement-level filters are supplied, narrative units simply do not match. No synthetic statement metadata is invented for narratives.

## Historical Safety

Historical results cannot be mistaken structurally for current knowledge because every returned row still carries:

- `source_layer_role = historical_precedent`
- historical case identity rather than Phase 5 document identity
- precedent availability and precedent type
- historical contamination and authority-disposition metadata
- historical provenance through the primary source locator

Lexical rank therefore means only:

- this historical precedent text is lexically relevant

It does not mean:

- this is current WNC policy

## Limited / Analyst Inference / Historical-Value Handling

`6.4B` keeps these units searchable rather than suppressing them:

- limited precedents remain in the surface by default
- analyst-inference lessons remain searchable and explicitly typed
- historical-value-only statements remain searchable and explicitly typed
- contamination risk and authority disposition remain visible

Representative high-risk retrieval behavior:

- `300 storage` returns the `HC-003` decision with `historical_value_only = true`, contamination `high`, and authority disposition `potential_conflict_with_current_knowledge`
- `current legal precedent` returns the `HC-009` decision warning that the historical ADE solution is not current legal precedent
- analyst-inference retrieval still exposes `lesson_kind = analyst_inference`

No ranking penalties or boosts were added yet for:

- limited status
- analyst inference
- contamination risk
- historical-value-only content

That policy remains deferred.

## Security

The historical lexical function remains private and server-side:

- schema placement: `private`
- function mode: `security invoker`
- fixed `search_path = pg_catalog, private, public`
- no dynamic SQL
- direct execution revoked from `public`, `anon`, `authenticated`, and `service_role`

This preserves the existing private retrieval posture.

## Issues Discovered

Two implementation issues were found and resolved:

- default `ts_rank_cd` favored long case narratives over narrower exact statement rows for some statement-level searches, so the final implementation uses the built-in length normalization `2`
- one initial narrative pgTAP assertion used a title-like query that still preferred HC-001 statement rows, so it was tightened to narrative-only wording

Open lexical limitations retained and documented:

- `whole venue clearing`
- `sensory-sensitive beauty event`
- broad ranking-tie cases such as `client operated event` and `WNC cleared the venue`

These remain appropriate candidates for later semantic evaluation rather than lexical overfitting.
