# Phase 6.2E Current-Authority Connectivity Foundation

Date: August 7, 2026

## Summary

Phase 6.2E implements the governed Phase 6 relationship layer that points historical case versions upstream to current authority in Phase 4 and Phase 5.

It adds:

- Phase-6-specific Phase 4 relationship vocabulary
- version-scoped links from historical case versions to stable logical rules
- version-scoped links from historical case versions to exact Phase 4 rule versions
- Phase-6-specific Phase 5 relationship vocabulary
- version-scoped links from historical case versions to stable governed knowledge documents
- version-scoped links from historical case versions to exact governed knowledge document versions
- stable/exact parent integrity for exact references
- draft-only mutability for all current-authority relationships
- activation-time validation against 6.2D `current_authority_disposition`
- private-by-default RLS and grant posture

This task intentionally stops before production corpus ingestion, historical retrieval, search units, embeddings, or answer generation.

## Phase 4 Connectivity

### Stable reference surface

Phase 6 reuses stable Phase 4 logical identity through:

- `public.logical_rules.rule_code`

`public.historical_case_version_logical_rules` means:

- this historical case version is materially relevant to a current deterministic rule concept

It does not mean:

- the historical case version defines, governs, or overrides that rule

### Exact reference surface

Phase 6 reuses exact Phase 4 rule-version identity through:

- `public.rule_catalogue.id`

`public.historical_case_version_rule_versions` records optional exact-version references when that precision is genuinely useful.

### Stable/exact integrity

Exact rule-version references cannot float independently.

Implemented rule:

- if a case version links to `rule_catalogue.id = X`
- and `X` belongs to `rule_code = Y`
- then the same case version must also have at least one `historical_case_version_logical_rules` row for `rule_code = Y`

This is enforced by:

- `private.assert_hcv_rule_version_parent_scope_complete(bigint)`
- deferred constraint triggers on both the stable and exact Phase 4 relationship tables

### Phase 4 relationship vocabulary

Seeded non-authoritative Phase 4 relationship codes:

- `relevant_to`
- `illustrates`
- `historical_precedent_for`
- `encountered_issue_related_to`

## Phase 5 Connectivity

### Stable reference surface

Phase 6 reuses stable Phase 5 current-knowledge identity through:

- `public.knowledge_documents.id`

`public.historical_case_version_knowledge_documents` means:

- this current governed knowledge area should be consulted when interpreting the historical precedent

It does not make the case version part of Phase 5 governance.

### Exact reference surface

Phase 6 reuses exact governed Phase 5 version identity through:

- `public.knowledge_document_versions.id`

`public.historical_case_version_knowledge_document_versions` stores optional exact-version references where exact governed-version context matters.

### Stable/exact integrity

Exact governed knowledge version references cannot float independently.

Implemented rule:

- if a case version links to `knowledge_document_versions.id = X`
- and `X` belongs to `knowledge_documents.id = Y`
- then the same case version must also have at least one `historical_case_version_knowledge_documents` row for `Y`

This is enforced by:

- `private.assert_hcv_doc_version_parent_scope_complete(bigint)`
- deferred constraint triggers on both the stable and exact Phase 5 relationship tables

### Phase 5 relationship vocabulary

Seeded current-guidance relationship codes:

- `current_guidance_to_consult`
- `current_context_relevant_to_case`
- `current_authority_supersedes_historical_practice`
- `current_document_for_interpretation`

## Authority Direction

Authority direction remains:

Phase 4 deterministic rules
→ Phase 5 governed current knowledge
→ Phase 6 historical precedent

Phase 6 points upstream to current authority.

Phase 6 never:

- copies current deterministic values into Phase 6 relationship rows
- copies current governed knowledge text into Phase 6 relationship rows
- derives Phase 4 or Phase 5 authority from historical precedent

This preserves `P6-INV-001 — Authority Separation`.

## Statement-Disposition Validation

Activation now validates case-version current-authority coverage against 6.2D statement metadata.

Implemented behavior:

- `check_phase_4`
  - requires at least one Phase 4 relationship
- `check_phase_5`
  - requires at least one Phase 5 relationship
- `check_phase_4_and_5`
  - requires at least one Phase 4 relationship and at least one Phase 5 relationship
- `potential_conflict_with_current_knowledge`
  - requires at least one current-authority relationship from either layer
  - also requires `contains_historical_value_only_content = true`
- `current_status_unknown`
  - does not require a Phase 4 or Phase 5 relationship by itself
  - does require `precedent_availability = 'limited'` at activation
- `no_current_rule_implication`
  - requires no current-authority relationship

Validation is intentionally case-version-scoped.

6.2E does not create:

- statement-to-rule links
- statement-to-knowledge-document links

That preserves the approved architecture boundary from 6.1 and 6.2D.

## Immutability

Current-authority relationships are part of the governed case-version snapshot.

Implemented behavior:

- draft case versions may insert, update, and delete Phase 4 and Phase 5 relationship rows
- once the parent `historical_case_versions.governance_status` is no longer `draft`, all four association tables become immutable
- corrections require a superseding historical case version rather than in-place rewrite

This preserves `P6-INV-009 — Version Supersession`.
