Production Stage B data is loaded in:

- `supabase/seed.sql`

- `npx supabase db reset` reconstructs the corpus deterministically
- Stage B extends the same nine draft `v1` rows created in Stage A

## Idempotence Approach

Statement tables use surrogate identities and do not expose a natural unique constraint.

For the controlled production Stage B bootstrap, the seed block therefore uses a deterministic draft-scope replacement strategy for `HC-001` through `HC-009` version `1`:

1. delete exact Phase 4 / Phase 5 version links for the targeted case versions
2. delete stable Phase 4 / Phase 5 links for the targeted case versions
3. delete statement provenance links for the targeted case versions
4. delete governed lessons, decisions, and responsibilities for the targeted case versions
5. reinsert the approved Stage B content
6. reattach every statement to the existing curated Historical Case Library association for that case version

This keeps the production corpus deterministic without weakening the governance model.
