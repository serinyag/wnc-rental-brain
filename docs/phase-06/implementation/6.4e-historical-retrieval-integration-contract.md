# Phase 6.4E Historical Retrieval Integration Contract

Date: August 8, 2026

## Scope Implemented

Task `6.4E` adds one stable server-side historical retrieval contract above the already-validated Phase 6 retrieval substrates.

Implemented in this task:

- one Python integration entry point for historical precedent retrieval
- query-text-first retrieval orchestration
- frozen production hybrid policy reuse
- historical embedding-state preflight
- explicit lexical fallback when healthy hybrid cannot run
- explicit error categories for unrecoverable failures
- result serialization that preserves the historical safety envelope
- focused Python integration tests
- end-to-end integration evaluation and readiness audit

Not implemented in this task:

- current-plus-historical retrieval fusion
- authority-aware cross-layer orchestration
- context-pack assembly
- RAG
- answer generation
- agent or workflow integration

## Query Embedding

The integration layer accepts natural-language `query_text`, not a caller-supplied query vector.

Embedding generation reuses the existing Phase 6 / shared semantic stack:

- `OpenAIEmbeddingsClient`
- `embed_query_text(...)`
- active historical embedding-model registry resolution
- existing environment/key-loading order:
  - shell environment
  - `.env.local`
  - `.env`

No new `.env` loader or duplicate model configuration source was introduced.

## Embedding-State Preflight

Healthy hybrid requires:

- one active retrieval-approved historical embedding model
- matching historical embedding coverage row
- `eligible_unit_count == current_embedding_count`
- `missing_unit_count == 0`
- `stale_unit_count == 0`

If the historical semantic corpus is incomplete or stale, the integration layer does not mislabel the request as healthy hybrid.

## Healthy Hybrid Path

When the historical embedding state is healthy:

1. validate query and filters
2. resolve the active historical embedding model
3. resolve and validate the current historical embedding coverage state
4. generate the query embedding from `query_text`
5. call `private.search_historical_case_units_hybrid(...)`
6. return the results without reordering them in application code

Frozen production retrieval policy:

- strategy code: `historical_rrf_balanced`
- configuration code: `historical_rrf_balanced_d20`
- `k = 20`
- lexical weight `= 1.0`
- semantic weight `= 1.0`
- candidate depth per retriever `= 20`

6.4E does not expose user-controlled overrides for these values.

## Fallback Policy

Fallback mode implemented:

- `fts_fallback`

Healthy mode:

- `hybrid`

Fallback triggers:

- embedding model resolution unavailable or ambiguous
- embedding configuration unavailable
- query embedding generation failure
- historical embedding corpus incomplete or stale

Fallback implementation:

- call `private.search_historical_case_units(...)`
- preserve validated deterministic lexical ordering
- preserve the historical safety envelope

No automatic semantic-only fallback was added.

## Fallback Labelling

Top-level response always distinguishes:

- `retrieval_mode_requested`
- `retrieval_mode_used`
- `fallback_used`
- `fallback_reason`

Mode values:

- `hybrid`
- `fts_fallback`

Known fallback reasons used by the integration layer:

- `embedding_model_resolution_failed`
- `embedding_configuration_missing`
- `query_embedding_failed`
- `historical_embedding_corpus_incomplete`

Degraded retrieval is therefore never mislabeled as healthy hybrid.

## Error Contract

Unrecoverable failures raise `HistoricalRetrievalError`.

Current error categories:

- `invalid_query`
- `invalid_filter`
- `database_unavailable`
- `hybrid_function_failed`
- `fts_fallback_failed`

Failure behavior:

- invalid input is rejected before OpenAI calls
- database unavailability is not silently converted into empty success
- lexical fallback failure raises explicit error rather than fake empty success

## Safety Metadata

The integration layer does not reinterpret historical precedent as current authority.

Every result remains explicitly:

- `source_layer_role = historical_precedent`

The contract preserves downstream safety markers, including:

- limited-precedent status
- analyst-inference status
- historical-value-only flags
- contamination risk
- current-authority disposition
- confidentiality metadata
- PI metadata
- provenance/source locator metadata
