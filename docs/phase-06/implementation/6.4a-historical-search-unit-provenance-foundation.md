# Phase 6.4A Historical Search-Unit & Provenance Foundation

Date: August 7, 2026

## Summary

Task `6.4A` establishes the governed historical retrieval foundation for the active Phase 6 corpus.

It adds:

- version-level historical search-unit processing state
- derived historical search units for the active corpus
- exact lineage from each search unit back to governed case content and evidence
- a current historical retrieval surface limited to eligible active historical precedent
- rebuild mechanics that deterministically rematerialize the derived layer from governed Phase 6 source tables

It intentionally stops before:

- full-text search functions or ranking
- embeddings, vectors, semantic search, or hybrid retrieval
- merging historical retrieval with current retrieval
- RAG or answer-generation behavior

## Derived Objects

### Processing State

`private.historical_case_version_processing`

Tracks historical search-unit generation state per `historical_case_versions.id`, including:

- generation status
- last attempted timestamp
- last succeeded timestamp
- retry count
- last error code and message

The final integrity rule allows a previously succeeded version to re-enter `in_progress` during a later rebuild without violating the processing-state model.

### Search Units

`private.historical_case_search_units`

Stores the governed derived retrieval unit for one historical source statement or narrative row.

Deterministic source identities:

- `case_narrative:<historical_case_version_id>`
- `responsibility:<historical_case_version_responsibility_id>`
- `decision:<historical_case_version_decision_id>`
- `lesson:<historical_case_version_lesson_id>`

Unit types implemented:

- `case_narrative`
- `responsibility`
- `decision`
- `lesson`

The table preserves:

- case identity and version identity
- precedent type and precedent availability
- case-level evidence strength
- unit-level evidence strength
- case-level and source-level PI metadata
- effective confidentiality
- actor type for responsibilities
- lesson kind for lessons
- `historical_value_only`
- `contamination_risk_level`
- `current_authority_disposition`
- generation strategy metadata

### Provenance Links

`private.historical_case_unit_sources`

Stores exact lineage from each search unit to:

- the case-version evidence association
- the typed statement-source row when the unit comes from a responsibility, decision, or lesson
- the primary trace row used to expose a stable retrieval locator

Integrity rules enforce:

- same-version lineage only
- correct provenance shape per unit type
- one primary trace per unit
- no source-less search units

### Current Retrieval Surface

`private.current_historical_case_search_units`

This private view exposes only the historical units that are eligible for current retrieval use:

- parent version `governance_status = 'active'`
- parent version `precedent_availability in ('active', 'limited')`

It deliberately excludes:

- `held`
- `archived`
- `draft`
- `superseded`
- `retired`

The view also exposes:

- effective confidentiality level code
- primary source locator
- primary source object identity
- source-link count
- the statement-level contamination and authority metadata needed to distinguish historical precedent from current knowledge

## Generation Model

The production corpus uses one governed row per derived search unit.

Current production result:

- narratives: `9`
- responsibilities: `35`
- decisions: `25`
- lessons: `43`
- total: `112`

Narratives remain one unit per case version because all production narratives are still modest in size and the governed statement rows already provide the necessary granularity.

## Rebuild Mechanism

Implemented functions:

- `private.rebuild_historical_case_search_units_for_version(bigint)`
- `private.rebuild_current_historical_case_search_units()`

Behavior:

- inserts or reuses the processing-state row
- rebuilds only eligible active historical precedent into the current surface
- upserts derived units by deterministic `source_key`
- fully replaces lineage rows per version so provenance stays exact
- leaves governed Phase 6 source tables untouched

Idempotency result:

- repeated rebuilds preserve logical unit identity
- repeated rebuilds do not mutate governed case versions, evidence associations, responsibilities, decisions, or lessons

## Security Posture

The derived layer remains private.

Applied controls:

- RLS enabled on new private tables
- direct table and view access revoked from `public`, `anon`, `authenticated`, and `service_role`
- rebuild-function execution revoked from non-owner roles

This keeps the historical retrieval foundation internal until a later surfaced API is intentionally designed.

## Issues Discovered

Two issues were found during implementation and resolved:

- the initial processing-state success constraint was too strict for repeat rebuilds after a prior success
- the exclusion-fixture test initially attempted an invalid `draft -> superseded` lifecycle transition instead of the governed `draft -> active -> superseded` path

## Deferred Scope

Task `6.4A` explicitly defers:

- historical FTS ranking functions
- embeddings and semantic retrieval
- hybrid retrieval
- any unified current-plus-historical retrieval surface
- answer generation
