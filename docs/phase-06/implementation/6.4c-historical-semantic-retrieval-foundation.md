# Phase 6.4C Historical Semantic Retrieval Foundation

Date: August 7, 2026

## Scope Implemented

Task `6.4C` adds the Phase 6 semantic-retrieval substrate over the governed historical search-unit layer created in `6.4A` and the lexical baseline created in `6.4B`.

Implemented in this task:

- private historical embedding-model registry
- private historical embedding storage tied to historical search units
- deterministic embedding-input construction and input hashing
- historical embedding completeness auditing
- private historical semantic search with deterministic ranking
- historical semantic filter support aligned to historical FTS
- focused pgTAP coverage for schema, search behavior, filters, safety metadata, privacy, and staleness detection
- local tooling for historical embedding backfill
- local tooling for semantic evaluation

Not implemented in this task:

- hybrid or RRF retrieval
- current-plus-historical retrieval fusion
- RAG
- answer generation
- workflow or agent integration

## Objects Created

### Embedding Registry

Created:

- `private.historical_case_embedding_models`

Purpose:

- keeps the Phase 6 historical embedding model identity separate from Phase 5 chunk embeddings
- records provider, model code, version, dimensions, config fingerprint, and retrieval approval state
- enforces one active retrieval-approved historical model at a time

### Embedding Storage

Created:

- `private.historical_case_embeddings`

Association:

- `historical_case_search_unit_id`
- `embedding_model_id`
- deterministic `input_content_hash`
- `generated_at`
- vector payload

The table remains derived and private. Embeddings are not governed source content.

### Deterministic Input Surfaces

Created:

- `private.build_historical_case_search_unit_embedding_input(...)`
- `private.build_historical_case_search_unit_embedding_input_hash(...)`
- `private.current_historical_case_embedding_inputs`
- `private.current_historical_case_embedding_coverage`

`private.current_historical_case_embedding_inputs` is the canonical current semantic-input surface for Phase 6.

`private.current_historical_case_embedding_coverage` is the minimal completeness audit surface for:

- eligible unit count
- current embedding count
- missing count
- stale count

### Search Function

Created:

- `private.search_historical_case_units_semantic(...)`

The function is Phase-6-specific and does not reuse the Phase 5 chunk-semantic search function.

## Reuse Decisions

Reused from Phase 5 where the pattern was genuinely generic:

- OpenAI embedding client and API configuration handling
- `EmbeddingModelConfig`
- config fingerprint construction
- batch planning helpers
- vector literal construction
- dimension validation
- query-embedding generation helper

Kept Phase-6-specific:

- embedding registry table
- embedding association table
- current embedding-input view
- completeness view
- semantic search function
- historical filters and historical result metadata

Phase 5 chunk-linked tables were not reused because their foreign-key semantics are bound to `knowledge_chunk_id`, not historical search units.

## Embedding Input

The deterministic historical embedding payload is:

1. `Case: <case_title>`
2. `Case code: <case_code>` when present
3. `Unit type: <unit_type>` when present
4. `Actor type: <actor_type>` when present
5. `Lesson kind: <lesson_kind>` when present
6. governed `search_text`

This keeps semantic indexing tied to the same governed unit used by historical lexical retrieval.

The implementation does not inject:

- Phase 4 rule text
- Phase 5 document text
- current-policy values
- LLM-generated summaries or paraphrases

Repository-aligned model:

- provider: `openai`
- model code: `text-embedding-3-small`
- dimensions: `1536`

This matches the approved Phase 5 embedding baseline.

## Generation

Historical generation is implemented in:

- `tools/phase_06_search/generate_embeddings.py`

Behavior:

- reads only `private.current_historical_case_embedding_inputs`
- registers or reuses the configured historical embedding model
- skips rows whose `(search_unit_id, input_hash)` pair is already current for that model
- batches remote embedding requests
- validates returned dimensions
- inserts only missing or stale embeddings for the historical model
- reports coverage plus missing and stale source keys

Idempotency mechanism:

- uniqueness on `(historical_case_search_unit_id, embedding_model_id, input_content_hash)`
- deterministic hashing of the embedding input
- coverage view distinguishes current from stale rows

Stale detection mechanism:

- if a current search-unit input hash changes, old embeddings remain historically stored
- the coverage view marks the unit missing from the current semantic surface and stale for the model

Retry posture:

- the tool is restartable
- failure does not create null or fake vectors
- affected work can be rerun safely once the external embedding dependency is available

## Search

Similarity metric:

- cosine distance via pgvector `<=>`
- result score returned as both `similarity_score` and `cosine_distance`

Vector strategy:

- exact search only
- no IVFFlat or HNSW index added in `6.4C`

Reason:

- the active corpus is only `112` historical units
- this matches the Phase 5 small-corpus exact-search precedent
- the existing lookup index on the embedding table is sufficient for model/unit/hash selection

Deterministic ordering:

1. cosine distance ascending
2. `case_code`
3. `unit_type`
4. `search_unit_id`

Supported filters:

- `case_code`
- `unit_type`
- `precedent_availability`
- `precedent_type`
- `lesson_kind`
- `historical_value_only`
- `contamination_risk_level`

## Result Metadata

Historical semantic results preserve the same historical-safety envelope as historical FTS, including:

- `source_layer_role`
- search-unit identity
- source key
- unit type
- governed search text
- semantic score and distance
- case identity and case-version identity
- precedent type and availability
- case and unit evidence strength
- actor type
- lesson kind
- `historical_value_only`
- `contamination_risk_level`
- `current_authority_disposition`
- confidentiality metadata
- PI metadata
- primary source-object identifiers
- primary source locator
- source-link count

Semantic similarity therefore means only:

- this historical precedent is semantically similar to the query

It does not mean:

- this is current WNC policy

## Security And Privacy

All new semantic objects remain private and server-side:

- schema placement: `private`
- no client-facing embedding calls inside SQL
- embedding and registry tables have RLS enabled
- direct table and view access revoked from `public`, `anon`, `authenticated`, and `service_role`
- direct execute revoked for the semantic search and embedding helper functions

Privacy boundary:

- only governed historical search-unit text is embedded
- raw evidence artifacts are not embedded
- Phase 4 rules are not embedded
- Phase 5 knowledge chunks are not embedded
