# 7.2E Phase 6 Historical Precedent Adapter

## Adapter entry point

Phase 7.2E adds `tools/phase_07_reasoning/phase6_adapter.py` with one stable Phase 7 entry point:

- `execute_phase6_plan(...)`

The adapter accepts:

- validated `QueryPlan`
- optional `QueryContext`
- optional `Phase7RuntimeConfiguration`
- optional injectable `historical_retrieval_fn`

It returns one frozen `LayerExecutionRecord` for `phase_6`.

## Thin-wrapper scope

7.2E is intentionally a normalization layer only.

The adapter reuses:

- `tools.phase_06_search.historical_retrieval.retrieve_historical_precedents(...)`

The adapter does not:

- redesign Phase 6 retrieval
- recreate hybrid ranking logic
- combine Phase 6 with Phase 4 or Phase 5
- resolve authority conflicts
- apply contamination decisions
- merge confidentiality across layers
- assemble the final Phase 7 context package

## Not-requested behavior

If `query_plan.phase_6` is absent or `query_plan.phase_6.required = false`, the adapter returns:

- `layer_id = phase_6`
- `requested = false`
- `execution_state = not_requested`
- `result_count = 0`

No historical model resolution, embedding generation, or retrieval work runs on this path.

## Query and filter propagation

The adapter uses:

- `query_plan.phase_6.query_text` when present
- otherwise `query_plan.query_text`

It forwards the supported Phase 6 filters unchanged:

- `case_code`
- `unit_type`
- `precedent_availability`
- `precedent_type`
- `lesson_kind`
- `historical_value_only`
- `contamination_risk_level`

The effective result limit comes from:

- `Phase7RuntimeConfiguration.phase_6_result_limit`

The Phase 6 intent-level `result_limit` is not used for execution in 7.2E.

## Execution-state mapping

The adapter preserves the Phase 6 retrieval outcome while converting it into Phase 7 layer states:

- healthy Phase 6 `hybrid` results become `success`
- Phase 6 `fts_fallback` results become `fallback`
- valid empty retrieval becomes `no_results`
- `database_unavailable` becomes `unavailable`
- other `HistoricalRetrievalError` categories become `failed`

Normalized Phase 6 items only ever use:

- `success`
- `fallback`

## Source-role and authority normalization

Every normalized Phase 6 item is stamped as:

- `source_layer_role = historical_precedent`
- `authority_tier_code = historical_precedent`
- `authority_priority = 3`

The native Phase 6 `source_layer_role` field remains preserved in `layer_payload`.

## Result normalization

Each Phase 6 row is normalized into `NormalizedResultEnvelope` with:

- stable identity keyed by `case_code` and `source_key`
- exact identity carrying `historical_case_id`, `historical_case_version_id`, and `search_unit_id`
- `summary_text` equal to Phase 6 `search_text`
- unit-specific `content_kind`
- shared `RetrievalMetadata`
- shared `ProvenanceEnvelope`
- shared `SensitivityEnvelope`
- native Phase 6 row fields preserved in `layer_payload`

Current content-kind mapping is:

- `case_narrative -> phase6_historical_case_narrative`
- `responsibility -> phase6_historical_responsibility`
- `decision -> phase6_historical_decision`
- `lesson -> phase6_historical_lesson`

## Retrieval metadata preservation

The adapter preserves Phase 6 retrieval labeling:

- `retrieval_mode_requested`
- `retrieval_mode_used`
- `fallback_used`
- `fallback_reason`
- `strategy_code`

It also preserves the bounded native retrieval payload for downstream reasoning:

- `configuration_code`
- `result_limit_requested`
- `result_limit_used`
- `candidate_pool_limit`
- serialized embedding model
- historical embedding-state summary
- row-level hybrid / FTS rank fields
- row-level semantic / lexical participation flags

The adapter does not rerank or reorder returned rows.

## Historical safety metadata preservation

The adapter preserves the Phase 6 historical fields needed for later authority and contamination logic:

- `precedent_availability`
- `precedent_type`
- `lesson_kind`
- `historical_value_only`
- `contamination_risk_level`
- `current_authority_disposition`
- `case_contains_historical_value_only_content`

These fields remain available in `layer_payload`, and the direct Phase 6 row stays structurally intact.

Narrative rows are preserved honestly when statement-level historical-value / contamination fields are null.

## Sensitivity preservation

The adapter maps Phase 6 sensitivity directly into the shared Phase 7 envelope:

- `effective_confidentiality_level_code -> confidentiality_level`
- `source_object_personal_information_status`, falling back to `case_personal_information_status`

Supported PI normalization includes:

- `yes -> yes`
- `no -> no`
- `unknown -> unknown`
- `present -> yes`
- `not_present -> no`

`de_identification_required` is set only when the normalized PI status is `yes`.

The adapter does not suppress or merge content at 7.2E.

## Provenance preservation

The adapter preserves bounded historical provenance through:

- `case_code`
- `source_key`
- `historical_case_id`
- `historical_case_version_id`
- `search_unit_id`
- `responsibility_id`
- `decision_id`
- `lesson_id`
- `primary_historical_case_version_source_object_id`
- `primary_source_object_id`
- `primary_source_locator`
- `source_link_count`

The provenance envelope remains metadata-only and does not fetch raw source evidence.

## Export surface

The package export surface now includes the adapter through:

- `tools/phase_07_reasoning/__init__.py`

## Explicit deferred scope

7.2E intentionally does not implement:

- Phase 7 context assembly
- cross-layer authority resolution
- historical contamination gating
- historical/current conflict handling
- cross-layer confidentiality resolution
- answer generation
- RAG orchestration
- persistence
