# 7.2B Hybrid Selective Query Planner

Date: August 8, 2026

## Planner Module

- `tools/phase_07_reasoning/query_planner.py`
- `tools/phase_07_reasoning/evaluation_scenarios.py`
- `tools/phase_07_reasoning/tests/test_query_planner.py`

## Input/Output Contract

The planner entry point is:

`plan_query(query_text, query_context=None, runtime_configuration=None) -> QueryPlan`

It accepts natural-language query text and emits the frozen `QueryPlan` contract from `7.2A`.

It does not execute:

- Phase 4 APIs
- Phase 5 retrieval
- Phase 6 retrieval
- context assembly
- answer generation

## Deterministic Safety Overrides

Implemented overrides:

- `current_deterministic_claim_requires_phase_4`
- `historical_reference_requires_current_authority_before_prescriptive_answer`
- `historical_commercial_claim_requires_current_authority`
- `current_guidance_request_requires_phase_5`

These run before and after query classification so mandatory authority layers cannot be dropped by later heuristic routing.

## Query Taxonomy Logic

Supported runtime classes:

- `deterministic_current`
- `current_guidance`
- `precedent_discovery`
- `mixed_current_and_precedent`
- `authority_verification`
- `unresolved_authority`

Final class assignment uses deterministic precedence:

1. historical reference plus current-policy verification
2. unresolved/confirmation-sensitive current-authority cue
3. mixed current plus historical request
4. precedent discovery
5. deterministic current
6. current guidance

## Phase 4 Domain Mappings

- `catering_supplier`
- `technical_inventory`
- `technical_capability`
- `service_rules`
- `facilitator_requirements`

The mapping is multi-label and lexical/heuristic rather than single-label.

## Phase 5 Trigger Rules

Phase 5 is required for:

- process and explanation requests
- site visit, handover, and communication guidance
- mixed current/historical planning where current guidance must accompany current authority
- authority-verification and confidentiality-boundary scenarios that need current governed guidance
- unresolved-authority scenarios without a safely reusable deterministic-only path

## Phase 6 Trigger Rules

Phase 6 is required for:

- explicit precedent discovery
- historical examples
- historical-to-current verification
- mixed current/historical reasoning
- contamination-risk scenarios where a past claim is being validated for current use

## Ambiguity Flags

Implemented ambiguity flags:

- `ambiguous_deposit_type`
- `ambiguous_current_vs_historical_intent`
- `ambiguous_technical_inventory_vs_capability`
- `insufficient_domain_context`
- `mixed_guidance_and_deterministic_claim`
- `historical_reference_with_current_policy_request`

These are intentionally limited to execution-relevant ambiguity only.

## Routing Confidence

The planner emits:

- `high`
- `medium`
- `low`

Confidence is deterministic and derived from:

- unresolved authority cues
- mixed or broadened routing
- domain ambiguity
- missing safe domain context

## Safety Augmentation

After initial class selection, the planner performs a second augmentation pass that may:

- add `phase_4`
- add `phase_5`
- add `phase_6`
- add safety overrides
- add reason codes

This pass never removes a required layer introduced by a stronger deterministic rule.

## Evaluation Methodology

The benchmark uses:

- `tools.phase_07_reasoning.evaluation_scenarios.EVALUATION_SCENARIOS`
- the canonical human-owned matrix in `docs/phase-07/PHASE_7_REASONING_SCENARIO_EVALUATION_MATRIX.md`

Evaluation measures:

- required-layer recall
- exact required-layer-set accuracy
- unnecessary-layer rate
- query-class accuracy
- Phase 4 required-domain recall
- Phase 4 exact-domain-set accuracy
- safety-override recall

## LLM Ambiguity-Resolver Decision

No LLM ambiguity resolver was added.

The deterministic/heuristic planner satisfied the 40-scenario benchmark and met the safety thresholds without introducing a model dependency.
