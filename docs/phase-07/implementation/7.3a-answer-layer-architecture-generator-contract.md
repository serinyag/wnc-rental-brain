## Decisions Made

### 1. Generator boundary is narrower than `ContextPackage`

Decision:

- introduce `AnswerGenerationInput`

Reason:

- finalized `ContextPackage` intentionally still carries internal-only audit context
- the future generator does not need suppressed projections, raw layer data, or internal provenance

### 2. Mixed-authority answers require claim frames

Decision:

- introduce `AnswerClaimFrame`

Reason:

- a single answer-level authority label is too coarse for mixed P4/P5/P6 answers
- claim frames preserve source-role separation without introducing a semantic verifier

### 3. Answer modes remain semantic, not security-driven

Decision:

- answer modes describe answer semantics
- security state continues to use existing 7.2G `generation_decision`
- degraded behavior continues to use existing `DegradedRetrievalState`

Reason:

- avoids duplicate enums for existing concepts
- keeps `allowed`, `allowed_with_restrictions`, and `blocked` as the single generation-permission vocabulary

### 4. Application-side validation is required before downstream delivery

Decision:

- introduce `validate_answer_result(...)`

Reason:

- prompt obedience alone is not a sufficient control surface
- grounding, warning preservation, and blocked behavior can be checked deterministically

## Architecture Choices

### Least privilege

The answer layer consumes only finalized generator-safe inputs. Suppressed/internal items are filtered out before `AnswerGenerationInput` is constructed.

### Claim-level historical discipline

Historical claim frames always carry:

- `historical_context_only=true`
- `current_authority_supported=false`

### Blocked behavior

Blocked generation is not just a prompt instruction.

It is reflected structurally by:

- `answer_mode=blocked`
- zero claim frames
- zero safe grounding
- explicit `blocked_reason`

### Safe grounding only

Answer-layer grounding can come only from 7.2G safe grounding references. Internal provenance is not reused.

## Alternatives Rejected

Rejected:

- passing the entire finalized `ContextPackage` to the generator
- adding a second security enum for restricted/blocked behavior
- using only answer-level authority labels without claim frames
- relying on prompt text alone for blocked enforcement
- introducing a semantic verifier or hallucination detector in 7.3A
