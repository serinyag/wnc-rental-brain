## Controlled Vocabularies

The implementation adds stable application-layer vocabularies for:

- runtime query classes
- source-layer roles
- authority-tier codes and priorities
- layer identifiers
- execution states
- reasoning states
- authority outcomes
- conflict type codes
- forbidden-inference type codes
- routing-confidence codes
- Phase 4 domain codes
- confidentiality levels
- personal-information status codes
- severity codes
- contamination-action codes
- generator-policy action codes

These vocabularies are explicit string contracts and are validated deterministically.

- Phase 5 and Phase 6 filter placeholders

No live routing logic exists yet.

## Normalized Result Envelope

The contract implements the approved:

`shared metadata header + layer-specific payload`

shape through:

- `NormalizedResultEnvelope`
- `StableIdentity`
- `ExactIdentity`
- `RetrievalMetadata`

Every normalized item carries:

- explicit source-layer role
- explicit authority tier and priority
- stable identity
- exact identity
- execution state
- optional reasoning state
- provenance
- sensitivity
- optional retrieval metadata
- future layer-native payload

The implementation does not flatten all layer fields into one giant flat object.

## Layer-Execution Contract

`LayerExecutionRecord` captures:

- layer ID
- requested flag
- execution state
- optional reasoning state
- fallback reason
- error category / safe message
- result count
- normalized items

Validation preserves the two-axis design:

- execution semantics
- reasoning semantics

## Sensitivity / Provenance Contracts

The implementation includes:

- `ProvenanceEnvelope`
- `SensitivityEnvelope`
- `ConfidentialityState`
- `GroundingReference`
- `GroundingState`

The Phase 4 default sensitivity decision is encoded through:

- `phase4_default_sensitivity()`

which defaults Phase 4 adapter outputs to:

- confidentiality: `internal`
- PI status: `unknown`

No strictest-wins resolver exists yet.

## Context-Package Schema

`ContextPackage` implements the approved stable midpoint structure:

- `query`
- `routing_plan`
- `layer_execution`
- `phase_4_context`
- `phase_5_context`
- `phase_6_context`
- `authority_resolution`
- `uncertainty_state`
- `confidentiality_state`
- `degraded_retrieval_state`
- `grounding`
- `generator_policy`
- `context_contract_version`

This contract is designed to be the future handoff boundary into answer generation.

No live context assembly exists yet.

## Generator-Policy Contract

`GeneratorPolicy` defines the future pre-generation guardrail contract, including:

- generation allowed or not
- allowed actions
- forbidden actions
- required warnings
- confidentiality restrictions
- PI restrictions

No prompt or LLM call exists yet.

## Configuration Schema

`Phase7RuntimeConfiguration` defines the minimal runtime configuration approved for 7.2A:

- `phase_5_result_limit` default `5`
- `phase_6_result_limit` default `5`
- `routing_ambiguity_behavior = broaden_current_authority_first`
- current-claim Phase 4 override toggle
- historical-prescriptive current-authority override toggle

It does not add tuning knobs for downstream frozen retrieval strategy internals.

## Validation Rules

Deterministic validation now covers:

- invalid controlled-vocabulary values
- role/tier/priority mismatches
- malformed query plans
- missing required routing subsections
- contradictory execution-state and result combinations
- invalid layer/item role alignment
- invalid context-package section alignment
- invalid degraded-state structure
- invalid confidentiality-state structure
- invalid generator-policy actions
- JSON-incompatible native payloads

## JSON Serialization Behavior

All contracts inherit `to_dict()` and `to_json()` behavior via the shared dataclass base.

The output is JSON-compatible and safe to cross:

- CLI boundaries
- API boundaries
- evaluation tooling
- future answer-generation boundaries

This task does not add deserialization helpers yet because no cross-process reconstruction need exists in `7.2A`.
