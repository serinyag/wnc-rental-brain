## Provider Integration Design

Chosen provider:

- OpenAI only

Chosen runtime default:

- configured request model: `gpt-5.6`

Observed served model during evaluation:

- `gpt-5.6-sol`

Reason for selection:

- current OpenAI text-generation path with strong structured-output behavior
- repository already standardized on OpenAI credentials for live semantic operations
- sufficient instruction-following quality for bounded contract compliance

Non-decisions:

- no multi-provider abstraction
- no provider fallback
- no production-permanent model decision inferred from the evaluation default

## Adapter Behavior

Implemented adapter:

- `OpenAIAnswerGenerator`

Config object:

- `OpenAIAnswerGeneratorConfig`

Primary behavior:

- accepts only `BoundedAnswerGeneratorRequest`
- maps bounded request data into a provider request
- performs one live OpenAI Responses API call
- requests strict structured JSON output
- returns provider-neutral dict payloads back to the 7.3B runtime
- captures safe usage metadata without affecting answer authority logic

Explicitly excluded from adapter scope:

- retrieval
- query planning
- Phase 4/5/6 execution
- authority resolution
- contamination logic
- database access
- web access
- tool calling

## Prompt Boundary

The provider prompt now enforces:

- supplied generator-safe context is the complete factual universe
- outside knowledge may improve wording only, never WNC facts
- authority metadata must be echoed exactly from the request
- historical material, when used, must be introduced with the literal label `Historical context:`
- answer text must remain concise and non-repetitive
- hidden/suppressed/internal-only material must never be surfaced

Prompt payload content is restricted to:

- query
- request-state metadata
- answer mode instruction
- claim frames
- safe grounding
- required warnings

Not sent:

- `ContextPackage`
- raw layer execution records
- full upstream context collections
- credentials
- raw restricted historical summaries
- raw PI-bearing historical text
- restricted raw provenance locators

## No-Tool Enforcement

Provider request contains:

- `0` tools

Structural proof:

- provider payload construction never includes a `tools` field
- offline boundary test verifies absence of tool definitions and unsafe upstream payloads

## Structured Output Behavior

OpenAI request path:

- Responses API
- `text.format.type=json_schema`
- `text.format.strict=true`

Returned fields are limited to the Phase 7 answer result contract:

- `status`
- `answer_mode`
- `authority_outcome`
- `generation_decision`
- `confirmation_required`
- `insufficient_current_authority`
- `degraded_context_present`
- `materially_affects_answer_completeness`
- `answer_text`
- `grounding_uses`
- `warning_codes`
- `failure_code`
- `answer_contract_version`

No chain-of-thought or hidden-analysis fields were requested.

## Failure Handling

Live-provider failures were mapped into existing 7.3B runtime semantics:

- missing API key: explicit initialization stop
- timeout: `generator_timeout`
- provider transport/auth/model failure: `generator_failure`
- malformed or empty structured response: `malformed_generator_response`
- schema mismatch: `malformed_generator_response`
- downstream contract mismatch after generation: `answer_validation_failed`

Runtime adjustment made:

- safe provider exception details are now preserved when available, without weakening the bounded runtime boundary

## 7.3C Live Tuning Sequence

Issues found and resolved on August 9, 2026:

1. `gpt-5.6` rejected `temperature`.
   Fix:
   - omit `temperature` by default for this model family.

2. One mixed current/historical scenario intermittently truncated under a smaller output cap.
   Fix:
   - raise `max_output_tokens` to `1500`
   - tighten prompt toward concise answers

3. One current-guidance scenario intermittently rewrote upstream metadata.
   Fix:
   - explicitly require exact metadata echoing in the system prompt and user payload

4. Historical-labeling evaluation initially over-counted cases that had historical frames available but did not actually use historical grounding.
   Fix:
   - require explicit historical labeling only when generated grounding actually uses Phase 6 material
