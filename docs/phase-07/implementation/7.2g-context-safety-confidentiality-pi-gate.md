# 7.2G Context Safety, Confidentiality / PI Gate

## Entry point

Phase 7.2G adds one stable post-7.2F safety function:

- `tools.phase_07_reasoning.context_safety.finalize_context_safety(...)`

`build_context_package(...)` now operates in two stages:

1. build the authority-resolved 7.2F package
2. finalize the package for the generator boundary through `finalize_context_safety(...)`

The stage can also be called directly for evaluation because it consumes an already-built `ContextPackage`.

## Input/output contract

Input:

- a valid authority-resolved `ContextPackage`
- optional `ContextSafetyConfiguration`

Output:

- a final `ContextPackage` that preserves:
  - internal authority context
  - internal grounding
  - authority resolution
  - unresolved state
  - degraded retrieval state
- and additionally carries:
  - final `ConfidentialityState`
  - final `GeneratorPolicy`
  - generator-safe projections in `generator_safe_context`
  - generator-safe grounding in `generator_safe_context.grounding`

## Confidentiality ordering

The implementation reuses the repository taxonomy:

- `externally_shareable`
- `internal`
- `commercially_sensitive`
- `restricted`

Deterministic ordering:

- `externally_shareable < internal < commercially_sensitive < restricted`

This matches repository seed/test ordering rather than alphabetical ordering.

## Strictest-wins algorithm

7.2G computes final effective confidentiality from generator-eligible projected items.

Rules:

1. build generator-safe projections for all internal context items
2. exclude fully suppressed projections from generator-visible context
3. compute the effective confidentiality from the remaining generator-visible items
4. if no generator-visible items remain, fall back conservatively to the strictest contributing level for fail-closed handling

Phase 4 defaults remain unchanged:

- confidentiality = `internal`
- PI status = `unknown`

## PI aggregation

7.2G keeps item-level PI metadata internally and computes a generator-boundary PI summary after projection.

Package-level fields finalized:

- `personal_information_status_summary`
- `personal_information_present`
- `de_identification_required`

Important behavior:

- PI-bearing items can become generator-safe without leaving `personal_information_present = true` if the projection is fully de-identified
- PI uncertainty survives through `pi_status_unknown`

## De-identification transforms

7.2G uses narrow deterministic transforms only.

Implemented policy:

- restricted historical precedent -> high-level historical summary
- PI-bearing historical precedent -> high-level de-identified historical summary
- sensitive current-guidance items -> high-level internal projection when needed
- raw source locators are replaced with safe code-based locators for generator-visible grounding

The implementation does not attempt generic NLP anonymization.

## Suppression rules

An item is fully suppressed from generator-visible context when:

- the source sensitivity explicitly disallows generation
- the detail is sensitive and non-material after minimization
- no safe generator-visible value remains

Suppression is auditable because:

- internal context remains intact
- `ConfidentialityState` records suppressed item IDs and reasons
- `generator_safe_context` keeps a suppressed projection record

## Safe generator projection

7.2G adds explicit generator-safe projection contracts:

- `GeneratorSafeItemProjection`
- `GeneratorSafeGroundingReference`
- `GeneratorSafeContext`

Each projection records:

- original `item_id`
- source-layer role
- generator visibility:
  - `visible`
  - `de_identified`
  - `suppressed`
- generator-visible summary
- safe source codes
- safe locator
- removed fields
- de-identified fields
- warnings
- suppression reason where applicable

This preserves a clear separation between:

- internal authority context
- generator-safe context

## Generator decision policy

7.2G finalizes one of:

- `allowed`
- `allowed_with_restrictions`
- `blocked`

Current decision rules:

- unresolved authority and confirmation-required states remain answerable
- degraded retrieval remains answerable when the safe outcome can still be expressed
- source-level generation prohibition on all material context blocks generation
- safety-finalization defects fail closed and block generation

## Degraded-mode packaging

7.2G finalizes:

- affected degraded layers
- per-layer execution states
- fallback reasons
- `materially_affects_answer_completeness`
- normalized generator warnings

Examples:

- Phase 5 fallback -> `current_guidance_retrieval_degraded`
- Phase 6 fallback -> `historical_retrieval_degraded`
- Phase 5 unavailable -> `current_guidance_unavailable`
- Phase 4 failed/unavailable -> `deterministic_layer_failed`

## Grounding safety

Internal grounding remains unchanged for audit.

Generator-visible grounding is separately projected and:

- references only generator-visible items
- does not reuse suppressed item references
- avoids raw sensitive locators
- preserves the minimum safe citation identity:
  - Phase 4: rule code-oriented identity
  - Phase 5: document code-oriented identity
  - Phase 6: case/search-unit code-oriented identity

## Failure behavior

If safety finalization fails:

- no unsanitized generator-visible content is returned
- generation is blocked
- a blocked reason is emitted
- projections are returned in suppressed fail-closed form only

## Stateless design

7.2G is stateless.

It adds:

- no persistence
- no Supabase writes
- no migration
- no external model calls

## Explicit deferred scope

Still deferred after 7.2G:

- answer generation
- prompt design
- RAG
- agents
- client-facing output modes
- external generation boundaries beyond `internal_generation`

This document therefore closes the Phase 7 context layer only.
