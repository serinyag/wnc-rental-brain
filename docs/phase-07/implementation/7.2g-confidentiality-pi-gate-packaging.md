# 7.2G Confidentiality / PI Gate and Final Context Safety Packaging

## Entry point

Phase 7.2G adds one explicit safety-gate module:

- `tools/phase_07_reasoning.confidentiality_gate.finalize_confidentiality_state(...)`

The gate is now called from:

- `tools/phase_07_reasoning.context_assembler.build_context_package(...)`

7.2G replaces the former provisional confidentiality merge in the assembler with a dedicated final gate.

## Final confidentiality behavior

7.2G enforces:

- strictest-wins effective confidentiality across all included context items
- explicit cross-layer PI detection
- explicit de-identification requirement propagation
- explicit suppressed-item accounting for generator-visible safety packaging

The returned `ConfidentialityState` now finalizes:

- `effective_confidentiality_level`
- `contributing_item_ids`
- `personal_information_present`
- `de_identification_required`
- `generation_allowed`
- `generation_restriction_reason`
- `suppressed_item_ids`
- `suppression_reasons`

## Suppression rules

7.2G does not delete suppressed items from layer context.

Instead it preserves them in:

- `phase_4_context`
- `phase_5_context`
- `phase_6_context`
- `grounding`

and marks them as suppressed in `ConfidentialityState` so a future generator can keep provenance while avoiding unsafe detail exposure.

Implemented suppression rules:

- source item with `generation_allowed = false` -> suppress using the source restriction reason
- PI-bearing item -> suppress raw PI-bearing detail
- restricted historical precedent -> suppress raw restricted historical detail
- PI-bearing restricted historical precedent -> suppress with a combined specific reason

Current suppression reason codes:

- `source_generation_prohibited`
- `pi_bearing_detail_suppressed`
- `restricted_historical_detail_suppressed`
- `pi_bearing_restricted_historical_detail_suppressed`

## Generation gating

7.2G now finalizes the package-level `generation_allowed` decision.

Current blocking rule:

- if every material authority item is source-restricted for generation, block generation and emit:
  - `generation_restriction_reason = material_context_source_generation_restricted`

Important 7.2G boundary:

- restricted or PI-bearing historical material does not automatically erase the context package
- instead it is preserved as suppressed context with explicit high-level-only / de-identification restrictions for the future answer layer

## Generator-policy packaging

`GeneratorPolicy` is now derived from final confidentiality state instead of the former provisional placeholder.

7.2G adds final policy signals for:

- de-identification required
- sensitive detail suppressed
- historical context must remain high-level when restricted historical precedent is present
- personal-information presence
- generation block reason when applicable
- degraded retrieval warnings alongside confidentiality restrictions

If the confidentiality gate blocks generation:

- `generator_policy.generation_allowed = false`
- `allowed_actions = ()`

Forbidden generator actions remain unchanged:

- independent retrieval
- deterministic invention
- precedent promotion
- conflict override
- confirmation erasure
- authority-gap filling

## 7.2G scope boundary

Implemented in 7.2G:

- final strictest-wins confidentiality merge
- PI detection and de-identification requirement propagation
- suppressed-item accounting
- final generation gating based on sensitivity policy
- final generator-facing confidentiality and degraded-mode packaging

Still not implemented:

- answer generation
- actual text-level PI transformation or name rewriting
- RAG
- agents
- persistence

7.2G therefore completes the pre-generation context safety layer while keeping answer rendering as a separate later boundary.
