# 7.2F Context Assembly, Authority Resolution, and Historical Contamination

## Entry point

Phase 7.2F adds one stable context-layer entry point:

- `tools/phase_07_reasoning.context_assembler.build_context_package(...)`

The entry point accepts:

- `query_text`
- optional `QueryContext`
- optional `Phase7RuntimeConfiguration`
- optional injectable planner and layer executors for tests

It returns one frozen `ContextPackage`.

## Selective execution flow

The runtime flow is:

1. build `QueryContext`
2. call `plan_query(...)`
3. execute only required layers through `_execute_or_not_requested(...)`
4. collect three `LayerExecutionRecord`s
5. detect historical contamination annotations
6. resolve authority
7. populate uncertainty, confidentiality, degraded-retrieval, grounding, and generator-policy envelopes
8. return the final `ContextPackage`

If a layer is not required, 7.2F returns:

- `requested = false`
- `execution_state = not_requested`
- `normalized_items = ()`

No unnecessary layer work runs.

## Adapter interfaces reused

7.2F reuses the existing stable interfaces only:

- `tools.phase_07_reasoning.query_planner.plan_query(...)`
- `tools.phase_07_reasoning.phase4_adapter.execute_phase4_plan(...)`
- `tools.phase_07_reasoning.phase5_wrapper.execute_phase5_plan(...)`
- `tools.phase_07_reasoning.phase6_adapter.execute_phase6_plan(...)`

7.2F does not directly call:

- Phase 4 RPCs
- Phase 5 hybrid SQL
- Phase 6 historical retrieval

## Context-package population

`build_context_package(...)` populates:

- `query`
- `routing_plan`
- `layer_execution`
- `phase_4_context`
- `phase_5_context`
- `phase_6_context`
- `authority_resolution`
- `uncertainty_state`
- `confidentiality_state`
- `degraded_retrieval_state`
- `grounding`
- `generator_policy`
- `context_contract_version`

Layer contexts remain structurally separate. 7.2F does not flatten them into one scored list.

## Authority-outcome logic

Authority resolution lives in:

- `tools/phase_07_reasoning.authority_resolver.resolve_authority(...)`

The resolver classifies exactly:

- `DETERMINISTIC_CURRENT`
- `CURRENT_GUIDANCE`
- `HISTORICAL_PRECEDENT`
- `MIXED_WITH_CURRENT_PRIORITY`
- `INSUFFICIENT_CURRENT_AUTHORITY`
- `REQUIRES_CONFIRMATION`

Important 7.2F behaviors:

- resolved Phase 4 truth always controls current deterministic answers
- Phase 5 can support current framing without overriding Phase 4
- Phase 6 stays precedent only
- unresolved current-authority gaps outrank historical relevance
- direct Phase 4 room-access restrictions may remain controlling current truth for authority-verification questions even when the Phase 4 row is operationally confirmation-coded

## Conflict-code logic

The resolver emits:

- `TYPE_A_P4_BEATS_P6`
- `TYPE_B_P5_BEATS_P6`
- `TYPE_C_P6_EXISTS_BUT_CURRENT_MISSING`
- `TYPE_D_P4_REQUIRES_CONFIRMATION`
- `TYPE_E_P5_FAILURE_P4_SURVIVES`
- `TYPE_F_LIMITED_OR_UNKNOWN_PRECEDENT`
- `TYPE_G_CONFIDENTIALITY_ESCALATION`

Conflict generation is deterministic and based on authority state, not retrieval rank.

## Unresolved-authority logic

The resolver emits explicit `UnresolvedAuthorityRecord`s for:

- `requires_confirmation`
- `manual_review_required`
- `insufficient_information`
- `no_applicable_rule`
- `insufficient_current_authority`
- `current_status_unknown`

Important 7.2F rule:

- historical precedent can explain context but cannot fill a current-authority gap

## Contamination-gate logic

Contamination detection lives in:

- `tools/phase_07_reasoning.contamination_gate.detect_contamination_annotations(...)`

Implemented patterns:

- historical price -> current price
- historical person capability -> current service
- historical concession -> current policy
- historical legal solution -> current guidance
- historical overtime handling -> current rate
- historical room use -> current access right

The gate emits `ContaminationAnnotation`s with:

- implicated historical item IDs
- consulted current-authority item IDs
- `context_only`, `requires_confirmation`, or `unresolved` action

The overtime matcher was intentionally narrowed so late build-up boundary questions do not get misclassified as current-rate questions.

## Generator-policy population

7.2F populates `GeneratorPolicy` from authority and degradation state.

Allowed actions:

- synthesize
- explain
- compare
- express uncertainty

Forbidden actions:

- independent retrieval
- invent deterministic values
- promote precedent into current authority
- override conflicts
- erase confirmation requirements
- fill authority gaps

Warnings and restrictions reflect:

- insufficient current authority
- confirmation requirements
- limited precedent
- degraded current guidance
- degraded deterministic authority
- provisional confidentiality and PI presence

## Grounding assembly

Grounding is assembled in:

- `_build_grounding_state(...)`

Each included context item becomes one `GroundingReference` carrying:

- `reference_id`
- `item_id`
- `source_layer_role`
- full provenance envelope

Phase 4 provenance was strengthened so technical-inventory items now fall back to `source_code:` locators when a direct file locator is unavailable.

## Failure behavior

7.2F preserves layer execution honesty:

- `fallback`
- `failed`
- `unavailable`
- `no_results`
- `not_requested`

Degraded behavior is surfaced through:

- `layer_execution`
- `DegradedRetrievalState`
- `GeneratorPolicy`
- conflict and unresolved-authority records where applicable

7.2F does not silently convert degraded layers into healthy layers.

## Stateless runtime

7.2F is stateless runtime assembly only.

No answer generation was added.
No final confidentiality merge was added.
No PI de-identification was added.
No RAG was added.
No agents were added.
No persistence was added.

## Deferred 7.2G scope

Explicitly deferred to `7.2G`:

- final cross-layer confidentiality merge
- PI minimization and de-identification
- generation blocking based on final sensitivity policy
- final degraded-context safety packaging

7.2F stops at the machine-readable, authority-resolved pre-generation context package.
